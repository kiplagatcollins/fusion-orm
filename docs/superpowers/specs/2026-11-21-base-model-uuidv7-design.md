# Design: gorm-parity base models with UUIDv7 primary keys

Date: 2026-11-21
Status: Approved (design walkthrough approved in session)

## Goal

Provide gorm.Model-style base models for fusion-orm: `fusion.Model` (numeric
autoincrement ID) and `fusion.UUIDModel` (UUIDv7 ID), where the UUID ID is
generated by the ORM at create time by default and the numeric ID is
backfilled from the driver.

## User decisions

1. **Two base structs** — switch between `uint`-style and UUID IDs by swapping
   the embedded struct (`fusion.Model` vs `fusion.UUIDModel`). No tag magic.
   Note: `fusion.Model` uses `uint64` rather than gorm's `uint` — the same
   width as `LastInsertID` (int64), avoiding truncation at the signed 64-bit
   boundary shared by both drivers.
2. **`DeletedAt` included** in both bases, wired to the existing soft-delete
   machinery (nullable timestamp, index).
3. **UUID Go type: `github.com/google/uuid.UUID`** (already an indirect
   dependency in go.sum; becomes direct, no new downloads).

## API

New file `model_base.go` in the root package:

```go
// Model is the gorm.Model equivalent: autoincrement ID, timestamps, and
// soft-delete DeletedAt. Embed by value.
type Model struct {
	ID        uint64    `fusion:"pk,autoincrement"`
	CreatedAt time.Time
	UpdatedAt time.Time
	DeletedAt DeletedAt `fusion:"index"`
}

// UUIDModel replaces the numeric ID with a UUIDv7 primary key.
type UUIDModel struct {
	ID        uuid.UUID `fusion:"pk,type:uuid"`
	CreatedAt time.Time
	UpdatedAt time.Time
	DeletedAt DeletedAt `fusion:"index"`
}
```

Usage mirrors gorm: embed by value; `fusion.Model`'s ID is filled after
insert (LastInsertID/RETURNING backfill, already implemented); rows are
soft-deleted by default, `Unscoped()` hard-deletes (existing machinery).

## Behavior: UUIDv7 generation

- Rule: a primary-key field of type `uuid.UUID` that is **not**
  `autoincrement` is generated with `uuid.NewV7()` when its value is zero at
  create time. Pre-set IDs are respected.
- Implemented as a precompiled closure on `schema.Field` (same pattern as
  `Appender`/`Scanner`/`IsZero`): resolved once at table init, zero per-row
  reflection beyond the existing `fieldAt` path.
- `insertRows` (callbacks_default.go) invokes the generator per row next to
  `setTimestamps`, before the INSERT is built — so the ID flows as a normal
  column value through INSERT, `RETURNING`, and batch paths. Batch inserts
  receive one unique v7 ID per row.
- Rejected alternative: DB-side `default:uuidv7()` — SQLite has no native
  uuid function, and the migrator renders `default:` verbatim into DDL.
- Rejected alternative: table-level callback mutation of `*Field` maps —
  leaks into exported API for no benefit.

## Storage

- `type:uuid` tag → `migrator.sqlType` renders native `uuid` on PostgreSQL
  (`PostgreSQLTypes` feature) and `TEXT` on SQLite.
- `uuid.UUID` implements `driver.Valuer` (string) and `sql.Scanner`
  (string/bytes), so existing appender/scanner paths work with both drivers
  unchanged.
- Non-goal for this design: native SQLite BLOB(16) uuid storage.

## Existing machinery relied on

- Embedded struct field flattening with prefix support (schema/table.go).
- Name-based metadata: `ID` → PK (schema/field.go:204), `CreatedAt` →
  AutoCreateTime, `UpdatedAt` → AutoUpdateTime, `DeletedAt` → soft delete
  (schema/field.go:188).
- `fusion.DeletedAt` nullable timestamp type (soft_delete.go).
- `typeCompatible` in the migrator treats `uuid`/`text` consistently via the
  new type mapping.

## Testing

- SQLite integration (temp file, no daemons):
  - `AutoMigrate` on a `UUIDModel` model creates the table with `TEXT`
    `id` column, index on `deleted_at`.
  - `Create` fills ID with a v7 UUID (version nibble check), respects
    pre-set IDs, fills CreatedAt/UpdatedAt, leaves DeletedAt NULL.
  - Batch create: unique IDs across rows.
  - Soft delete/`Unscoped`/`Restore` on a `UUIDModel` model.
  - `fusion.Model` parity: backfill + timestamps + soft delete.
- PG paths env-gated via `FUSION_TEST_PG_DSN` (native `uuid` column type).
- Table-driven tests beside the code they cover (AGENTS.md).

## Error handling

- `uuid.NewV7()` failure (clock regression handling is internal to
  google/uuid; error path) → surfaced via `db.AddError` wrapped with
  field context, aborting the create.
- No new sentinel errors; no panics in library code.
